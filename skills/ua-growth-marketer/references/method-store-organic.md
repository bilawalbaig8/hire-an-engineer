# Method: Store and organic (ASO, store tests, ratings, SEO basics)

## 1. When to read this
A store page review, keywords, a store listing test plan or the read of a finished test, getting more ratings, SEO basics for the game website or press page.

## 2. Listing review
1. Read the current listing (text from the brief or the live store page) and the store's live listing and metadata pages (`policy-flags.md`).
2. Review the name, subtitle or short description, keywords and what the first screenshots must say. Character limits come from the live page with URL and date, or are `unknown`.
3. Choose keywords and say why (what players search for, what the game really offers; the Game Designer's view when the brief gives it). No keyword stuffing, no competitor names, no unsourced "number 1".
4. Brief the Writer for the new text (limits, keywords, one key message, claims list). Screenshot look is the Creative & Art Director's; caption words are the Writer's.

Template: `Field | Now | Problem | Keyword or message | Limit (live page, date) | Brief for the Writer | Claims`

## 3. Store listing test
1. One question per test, one thing changed. Use the store's own tool (Apple product page tests and custom product pages, Google Play store listing experiments and custom store listings); read their live help page for the current limits.
2. Read a finished or running test with the store's own result. If the console says more data is needed, the answer is wait.
3. Applying a variant is a person's click: return it as `needs_approval` with the named person.

Template: `Question | Variant change | Store tool | Store's own result (quoted, date) | Recommendation | Who applies`

## 4. Ratings and reviews the allowed way
The official in-app rating prompt at a good moment, and replies to reviews (drafted for the Writer and a person to post). Never pay, reward or gate for a rating, and never ask only happy players by a trick. Refuse and name the store's ratings policy.

## 5. SEO basics
A clear title and description per page, pages written for people, a press page with facts that have sources. No keyword stuffing, no spam tricks, no programmatic SEO or link buying. Read the Google Search Central pages in `policy-flags.md`.

## 6. Where files go
`docs/marketing/store/` (listing briefs, store-test plans and reads, SEO notes); flags in `docs/marketing/flags.md`.

## 7. Traps
- "Variant B is up after 3 days; the console says more data needed; apply it": wait, quote the store's result, applying is a person's click.
- "Give gems for a 5-star rating": refuse, name the ratings policies, propose the official prompt.
- "Title: Best Puzzle Game #1 Free Match 3 Puzzle Puzzle": rewrite inside the metadata policy, mark "#1" as needs source.

## 8. Done when
The brief or plan is in `docs/marketing/store/`, limits come from live pages with dates, claims are listed, test reads quote the store's own result, and applying or publishing is returned as an approval.
