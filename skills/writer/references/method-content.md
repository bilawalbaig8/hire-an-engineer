# Method: Content mode (store pages, ad copy, posts, email and landing-page text)

## 1. When to read this
Store page text (app name, subtitle, short and long description, what's new), ad headlines and short text, social, launch and update posts, email text, landing-page text.

## 2. Steps
1. Read the brief: the reader, the product, the format, the limits, and what must not be said. Read `voice-and-style.md` and `claims-and-sources.md`.
2. Read the style guide and glossary in `docs/writing/`; if none exists, draft a short one marked `draft`.
3. Find what is real: the product, its feature list, any data file for numbers. List the facts you may use.
4. Read the live platform page for limits and rules (for example the store's product page or store listing help, the ad platform's text specs). Write the URL and date. A limit you could not read is `unknown`.
5. Write the copy, main point first, inside the limits. Count characters with a command or a small script and give the count.
6. Write versions that change one thing each, with names.
7. Make the claims list (`claims-and-sources.md` section 2).
8. Return it as a draft with an approval to publish (`needs_approval`, `one_way_door: true`), naming who would publish.

## 3. Where files go
`docs/writing/content/` (one file per piece or campaign, with its claims list), unless the brief names another folder.

## 4. Lines with other roles
- Keywords, store keyword strategy, budgets, targeting, which ads run and which tests run: UA & Growth Marketer. You write the words for the keywords and tests it gives (owner decision Q2).
- Words on screens (buttons, errors): Designer.
- The big idea: Creative & Art Director.

## 5. Traps
- The brief asks for an unbacked claim ("number 1", "10 million downloads"): leave it out or mark it `unknown`, ask for the source, offer honest lines.
- The brief states a character limit: check it on the live page; never trust it silently.
- "Write player reviews" or "post it now": refuse the reviews, draft the post, return posting as an approval.
- A launch calendar is a draft too; a named person posts.

## 6. Done when
The copy fits the limits read today (or the limit is marked `unknown`), every claim has a status, the versions change one thing each, and the answer lists the approvals needed and the checks not done.
