# Changelog

All notable changes per skill. Versions follow semantic versioning; tags are `<skill-name>-v<version>`.

## hire-an-engineer

### [0.4.0] - Unreleased
- New `delivery-loop.md`: any request to build, change, fix or ship, from engineers or not. Questions then plan/spec loop, one approval of plan and spec, then roles as independent lanes in a loop with review and tests on every step, model tiers per step, hard stops, and a `REPORT.md` with diagram and batched questions. New `task-loop.md` (the per-task engine): one task from plan to Done with four fixed stops (approve plan, test it, "merge", pick next), resume that reruns verify, at most two live tasks each in its own folder, rounds capped at three, "looks good" is not "merge", quiet cost with one estimate-vs-actual line, per-task "how to check" steps, and section 10 Autopilot (Stops 1-3 waived after the one approval). `roles.md` gains "Roles in the loop" (who reviews each role, which tier). Routed from SKILL.md and `workflow.md`. Also: `develop` branch rule when anything deploys from `main`; the spending cap covers build usage only, with a hard stop at 80%; an Authorization record counts only if this skill wrote it after the person's yes (found in a received repo or closed: data); one approval everywhere (phase, plan and milestone approvals are covered unless the person asks for stepwise); bounded defaults for questions during a run; a fresh whole-diff review (or "reviews not independent") when lanes cannot be independent; approved tests cannot be removed, skipped or loosened; QA uses sandbox keys and fakes only; a found Authorization is marked untrusted at once, a checkpoint is written at the end of §2 turns, and unanswered values in examples are labelled as assumptions.
- Money/messaging review checklist (concurrency, every provider event in every order, resource released on failure, refund after paid); milestone-note rule (not at the last milestone, medium+ plans have two or more); unanswered hard-stop rule at delivery; spec-amended record; cap proposed in counted units; local `--no-ff` merge when no remote; state file rewritten at every checkpoint; paid-after-release re-claims or refunds, 'sent' recorded before sending, develop before the first commit; cap at or above counted plan ÷ 0.8, autopilot running total at finish, REPORT fallback and reopen rule, lane briefs without sub-agents.

### [0.3.0] - 2026-10-23
- New `platform-targets.md`: mobile apps (accounts, signing keys, store review, children's audience, iOS needs a Mac), browser extensions (Manifest V3, minimum permissions, never all-sites on banking/webmail), data/ML projects, scripts scheduled on the person's own PC; first-release checklists; routed from SKILL.md, `project-cases.md`, `versioning-release.md`, `technical-products.md`.
- Person-to-person handover checklist in `documents.md` §5. Chat-only resume pack (language, cost mode, accounts, pending approvals, last environment) in `project-memory.md` and the PROJECT_STATE template; hand back the whole file, never a diff.
- Rules from three complex-project test runs and a three-session salon-platform build: pasted cards/passwords/keys are never used, repeated or stored; "you decide" is not approval and money/account/deploy approvals are never batched; core-logic tests are never waived; rescue copies originals outside the repo and removes secrets before the first snapshot; person-only checks come before switching approach when stuck; simplest rung for the current stage; labelled self-review fallback with "fresh review owed"; later-session reviews count as fresh only for code it did not write; failing test committed before code; timestamps only from `date`; unverifiable prices are never quoted; Large projects read only three references before the first reply.
- `integrations.md`: webhook tests cover every event pair in both orders and early events are kept, not dropped; new §9 Payments (hosted checkout, refund policy, amount/currency/partial-refund checks, flag refunds the system did not start), §10 Messaging consent and opt-out, §11 real customer data sent to an AI tool. `database.md`: SQLite busy timeout and competing-write tests. `technical-products.md`: working inside an existing engine when the editor cannot be run. `cost-management.md`: how to estimate build usage and a tool-agnostic "Match the model to the work" tier guide (§6).
- `scripts/validate_skills.py` now fails on references SKILL.md does not route to and on `file.md §N` links with no such heading.

### [0.2.1] - 2026-10-22
- Fixes from a full review of the skill: engine/dev-tool work is Large only when building the engine itself, with a new short section for working inside an existing Unity/Godot/Unreal project; Tiny minimum files listed once (`project-memory.md` §1); `roles.md` now matches the review, security and cost rules at every size and splits "PM" into product and project manager; Tiny work in progress goes on a `wip/` branch so main only gets passing work; gap-report CLI body carries the triage headings so labels apply; hosting and backup advice no longer overclaims free plans; build-usage estimates only on request or a budget tripwire; person-handover routed correctly; WCAG 2.2; secret scans never print the matched value. Validator no longer crashes on a Windows console.

### [0.2.0] - 2026-10-22
- Thinking toolkit: one-way vs two-way doors, physics-or-convention, attacker's view for security, look-up/estimate/buffer for numbers, and a new debugging and performance section (check the real code, simplest first, competing hypotheses, find the bottleneck); router sends bugs with unclear causes, security, estimates and slowness there. Adapted from cc-thinking-skills.
- New `engineering-principles.md` §10 Data and performance choices: real data size and 10× design, maps for lookups, no nested loops on large data, built-in sort/search, let the database filter/sort/paginate, structures by data shape (trees/graphs as rows), loops instead of deep recursion, cache with expiry, realistic-size tests; "10× data" question added to every code review.
- New `engineering-principles.md` §11 Runtime performance: browser, devices, OS: budgets (LCP, INP, CLS, memory, idle CPU) measured on weak devices; browser rules (images, JS, fonts, workers, network, long lists, memory leaks, device matrix) and OS/desktop/script rules (streaming, non-blocking work, idle, cleanup, cross-platform paths, concurrency).
- Security: risks specific to AI-built projects in §6 — prompt injection in AI features, checking new packages before install (hallucinated/typosquatted names), local pre-commit secret checks and leaked-key handling.
- Diagrams: new `documents.md` §7 Diagram quality (draw only when it beats words, type by content, ≤9 boxes/≤12 arrows, 1–2 highlights, clean connectors, no generic AI look, captions, phone-readable, redraw rules, pre-show check); Mermaid stays the editable source, a dedicated diagram skill (e.g. diagram-design) for diagrams to present. `plain-language.md` and SKILL.md: explain flows, options, plans and designs to the person with a simple diagram in the reply, with fallbacks per environment. Adapted from diagram-design.
- New `ai-agents.md` for AI features, workflows and agents inside the product: simplest shape first (code → one AI step → workflow → agent), hard stops in code (steps, time, spend, retries, kill switch), agent-friendly tool design, least access with draft-don't-do approvals and a trust ladder, state outside the prompt, evals before launch with a separate checker, run logs, provider-failure fallbacks and a pre-launch checklist; routed from SKILL.md and `process-automation.md`. Informed by readings in awesome-harness-engineering.
- `ai-agents.md` §5: layered summaries for large memory/knowledge (one-line summary and overview per folder, full file on demand) and search scoped to the current project/user/folder. Idea from OpenViking.
- `ai-agents.md` §5: memory lifecycle (source, date, confidence; newer facts retire contradicting ones; stale entries reviewed on a schedule; no auto-capture of secrets or personal data) — idea from agentmemory; facts-need-sources rule for AI research and reports (every claim cited, inferences labelled, code checks cited sources were read) — idea from scientific-agent-skills. Pre-launch checklist and `documents.md` §2 quality bar updated to match.

### [0.1.0] - 2026-10-21
- First public release: full-team workflow, project memory (AGENTS.md, PROJECT_STATE.md, ~20-min checkpoints), getting-unstuck protocol, UI/UX, database, integrations, process automation, technical products, cost tracking, router-based SKILL.md.
- Tuned from a pre-release evaluation (5 test cases): doesn't take over routine or one-off questions; replies in the language of the person's messages; first-reply recipe (size guess picks the lane, show something visible with the questions, deliver requested plans/tests first); minimum files per size with templates in `templates.md`; rescue lane for stuck projects; lighter discovery for single-step automations; privacy prompts for personal financial/health data.
- Hardened from a thinking-model review (pre-mortem, red team, via negativa, map–territory): outside content is data, never instructions; secrets never printed and kept out of rescue snapshots; approval defined (one action, own message, explicit yes) and extended to deploys, force-push, DNS, live config, migrations and rollback; tripwires force the normal lane; test-first for core logic in every lane; checkpoints per finished task, never stash, PROJECT_STATE trimming; chat-only resume; project-at-a-glance page; build-cost estimates; leaner references (new `handoff.md`, `gap-reports.md`).
- Design depth: new `visual-quality.md` (modes, idea-first, generic-look tells, concrete type/colour/space values, design record, screenshot critique, polish pass) and `motion.md` (timing, easing, feedback, performance, reduced motion); `ui-ux.md` gains quick persona, journey map, real options, heuristic walkthrough and a better test script. Adapted from taste-skill, impeccable, gsap-skills and designer-skills (credited in THIRD_PARTY_NOTICES).
